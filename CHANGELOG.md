# Changelog

Versions are tagged `vX.Y.Z`. Small fixes bump the last number; features and large fixes bump the middle one.

## 0.3.0

**Draft.** Items marked TODO are waiting for the runtime work or a test on the finished build. Delete a line when it is
not true of the release, and remove the marks and this line before tagging.

**The runtime is now LAS Recomp's.** The runtime and the game code generator are rebuilt on LAS Recomp's current engine
(copied at the commit in [docs/UPSTREAM.md](docs/UPSTREAM.md)) instead of the October fork of it this port started
from, so later LAS fixes can be merged in instead of ported by hand. Kirby's part is a small layer next to it
(`game/`). Because the game code is generated by a different generator, every player builds it again: the launcher
says so and offers "Rebuild game code" (about 15 minutes; the game folder is not needed again).

No game files and no game code are included. The zip holds tools only; the game code is built on your PC from your
own extracted copy (base game, v1.0.0).

### Changed
- Built on LAS Recomp's runtime. Graphics, audio, input and the in-game menu (F1 or Esc) are LAS Recomp's: its
  settings, its Controls page, its pause handling. The keyboard keys changed: K J L I are A B X Y, Enter is Plus. The
  release `README.txt` lists them
- The game code needs a CPU with AVX2 (Intel Haswell, 2013, or newer; AMD Excavator or Zen, or newer). 0.2.0 also
  built for older CPUs. TODO (engine): decide whether the old level comes back
- The log of the last run is `game.log` (and `game-backup-*.log` for earlier ones), as the README says
- The launcher's Resolution setting matches LAS Recomp's: Match the display, 75%, 50% or 25% of it, 1080p, 4K. It
  wrote a key the runtime does not read before
- Ambient occlusion and the other letsgo-recomp graphics options are gone: the graphics are LAS Recomp's.
  TODO (retest): the beach cutscene and the first stage against 0.2.0

### Fixed
- A crash when a tutorial clip played, and a finished movie's buffers kept for the next one (carried from 0.1.1).
  TODO (engine): the movie buffer fix is not in the new runtime yet
- A condition variable wait lost its wake-up, which froze about 5 in 7 boots in testing: its key is now stored before
  the mutex is released
- The generator took the table of an indirect jump for functions, so jump tables inside functions were cut
  into pieces: a table's targets stay inside their function
- Black or half-drawn scenes while shaders for a new area build, with no word to the player: frames whose draws wait
  for builds are held, and a "Preparing graphics for this area... (first visit only)" notice shows after a second.
  TODO (engine): re-implement on LAS's renderer, then measure on 2 CPUs with a cold cache (0.2.1 branch: 168 s until
  every draw was drawn on the beach, 17 s with the table fix below)
- Pipelines of skinned models took 1 to 5 s each to build on a cold NVIDIA driver cache, because every instruction of
  a shader with an indirect branch became a case: only the jump table's targets do. LAS Recomp's translator has this.
  TODO (retest): summed pipeline build time on the scripted run (0.2.1 branch: 4601 s to 212 s)
- The translator lacked `VOTE.VTG`, the conditional `EXIT`, the `LEA` forms, shared-memory loads and stores, and image
  stores. TODO (engine): port them (they were in 0.1.0 and 0.2.0)
- Save file reads and writes were not logged. TODO (engine): the log match in `services/fs.c`
- The crash report's first line was cut off by the trace, and a lost graphics device read as a missing driver.
  TODO (engine): `dispatch.c` and `crash_explain.c`
- The launcher: closing it now ends a build in progress and the compilers under it, and a build that would fail on a
  full disk or a path over about 200 characters says so before it starts
- The launcher says what to do when the build tools are missing (an antivirus may have removed them), when the
  graphics driver has no Vulkan 1.3, and when the game closes within seconds of starting
- The launcher names a folder that holds the game's update (program id ending E800) instead of calling it another game.
  TODO (engine): `--check` and `--prepare` exit code 15 (docs/launcher-runtime-contract.md)
- After unzipping a new version over an old one, the launcher offers "Rebuild game code" instead of Play.
  TODO (engine): `--status` and `--rebuild-code` (docs/launcher-runtime-contract.md)

### Added

- `tools/audio_check.py`, a check of a capture of the game's sound; `tools/input/stage1.txt`, a script that plays the

## 0.2.0

**0.1.1 could not be set up from a normal dump. This version fixes that.** The game is still not playable: it has
only been run through the opening and the start of the first stage.

No game files and no game code are included. The zip holds tools only; the game code is built on your PC from your
own extracted copy (base game, v1.0.0).

### Fixed
- "No game files were found in that folder" for a folder that holds `exefs` and `romfs`
  ([#4](https://github.com/scarxity/kirby-forgotten-land-recompiled/issues/4)). The setup looked for a folder that
  this game's data does not have, so only a folder with a ready-made `romfs.bin` was accepted
- The launcher refused folders the setup accepts: `exefs` and `romfs` under other names, or one level further down
- A folder with more than 64 folders in it (a Downloads folder) could hide the game from the search

### Changed
- The launcher and the setup now use one search, so they always agree on a folder
- The "no game files" message says what a valid folder holds: `exefs` with `main` and `main.npdm`, `romfs` with the
  folders `msg` and `gfx`

### Added
- `--check <folder>` in the runtime: says whether a folder holds the game, without changing anything

### Known issues
- Each tutorial clip's window stays black for its first few seconds
- Frame generation does not work: leave it off
- Online features do not work: choose "Do Not Use" at the prompt
- Performance: about 30 fps in 3D, with pauses while graphics pipelines compile
- Only extracted `exefs` and `romfs` folders are accepted, not `.nsp` or `.xci` files
- After unzipping a new version over an old one, build the game code again from the Set up page

## 0.1.1

The first version with a download. **The game is still not playable**: it has only been run through the opening and
the start of the first stage.

No game files and no game code are included. The zip holds tools only; the game code is built on your PC from your
own extracted copy (base game, v1.0.0).

### Highlights
- **A download that needs no developer tools.** Unzip `ForgottenLandRecomp-0.1.1-Windows-x64.zip`, open
  `ForgottenLandLauncher.exe`, pick your game folder, Build, Play. The first build takes about 16 minutes on a
  16-thread PC and about 6.5 GB of disk.
- **RecompLauncher support.** The zip carries a `recomplauncher.json`: RecompLauncher can set the game up from your
  folder, show the Window, Resolution and Volume settings, and start it.

### Added
- The release zip: the launcher, the runtime, the code translator and a compiler, with their licences
- `--setup <folder>` and `--prepare <folder>` in the runtime: the setup with no window, for the two launchers
- A notice on the launcher's Home page when the game stops unexpectedly, with the reason and a kept copy of the log
- The build progress names the file being compiled once it has taken more than a minute

### Fixed
- A crash in the first stage when a tutorial clip played: a finished movie's buffers were kept for the next movie
  although the game had already reused that memory

### Known issues
- Each tutorial clip's window stays black for its first few seconds
- Frame generation does not work: leave it off
- Online features do not work: choose "Do Not Use" at the prompt
- Performance: about 30 fps in 3D, with pauses while graphics pipelines compile
- Only extracted `exefs` and `romfs` folders are accepted, not `.nsp` or `.xci` files
- After unzipping a new version over an old one, build the game code again from the Set up page

## 0.1.0

First tagged version, source only. The game boots, plays its opening and reaches the first stage with correct
graphics.

### Added
- The generator and runtime, imported from letsgo-recomp (MIT, built on LAS Recomp) and retargeted to this game
- Shader translator support for `VOTE.VTG`, `EXIT` flow tests, `LEA`, shared-memory loads and stores, and image
  stores with Vulkan storage images
- A launcher: pick your game folder, build the game code, play
